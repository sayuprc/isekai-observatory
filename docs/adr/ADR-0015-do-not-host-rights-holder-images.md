# 権利者の画像素材を保存・配信しない

## Context

リリースのジャケットアートを自前ストレージに保存し、Cloudflare の画像変換を通して配信しようとしていた
当サイトは非公式のファンアーカイブであり、権利者に帰属する画像を自前で保存・配信することを許諾なしに正当化できない

代替として公式サイトの画像をホットリンクする案も検討したが、`srcset` もリサイズもキャッシュも相手任せになり
LCP を制御できない。相手のトラフィックを消費する点も筋が悪い

一方で YouTube のサムネイル (`i.ytimg.com`) は事情が異なる
自前配信ではなくプラットフォーム自身の CDN から配信され、埋め込みでの利用が想定されている

表示上の識別子としては、ジャケットから抽出した代表色 1 色があれば足りることをモックで確認した

## Decision

権利者に帰属する画像を保存・配信しない
ジャケットアートは viewer・コントラクト・DB・ストレージのすべてから削除する

例外として、プラットフォームが自身の CDN で配信し埋め込みが想定されている画像 (YouTube サムネイル) は
直参照してよい。ただし自前ストレージへ複製しない

画像の代わりに、著作物性を持たない派生データとして代表色を 1 色だけ持つ
派生データは「元の表現の本質的特徴を直接感得できない」水準に留める
単色は可とし、複数色を元の配置のまま並べる・モザイク化する・縮小画像を出すことは行わない

色を得るために画像を一時的に受け取ることは許容する。受け取った画像は保存も配信もしない

代表色に関する部分は ADR-0034 で置き換えた

## Consequences

### Positive

- 権利者の画像を配信しない状態が構造として保たれる
- 画像の転送量とストレージが減り、LCP のクリティカルパスから画像が外れる
- 外部オリジンへの依存とホットリンク先の都合に左右される要素が減る

### Negative

- リリースの視覚的な識別力が落ちる。色 1 色は作品を思い出す手がかりとしては弱い
- `og:image` をリリースごとに出せず既定画像に落ちるため、Twitter カードが `summary` になる
- 代表色は管理画面で画像から候補を出して人が選ぶ運用が要る(一括自動決定はしない)
