# 全般的なコードレビューチェックリスト

## セキュリティ
- [ ] 入力のバリデーション(ユーザー入力を決して信用しない)
- [ ] SQL インジェクション対策(ORM/クエリビルダのバインディングを使用する)
- [ ] XSS 対策(テンプレートでの適切なエスケープ)
- [ ] 状態を変更するリクエストでの CSRF 保護が有効か
- [ ] 認証と認可(RBAC)のチェックが行われているか

## パフォーマンス
- [ ] N+1 クエリ問題を避けているか(Eager Loading の使用)
- [ ] データベースカラムに適切なインデックスが貼られているか
- [ ] メモリや処理を効率的に使用しているか(可能な限り巨大なループを避ける)
- [ ] アセットの最適化(フロントエンド)

## 可読性 & 保守性
- [ ] 変数名や関数名が意味をなしているか
- [ ] 小さく、単一の責任を持つ関数/クラスになっているか(単一責任の原則)
- [ ] コメントは最小限か(「何をしているか」ではなく「なぜしているか」に焦点を当てる)
- [ ] プロジェクト全体で一貫した命名規則に従っているか
- [ ] DRY(Don't Repeat Yourself)が適切か(時期尚早な抽象化を避ける)

## エラーハンドリング & ログ
- [ ] 機密情報がログに記録されていないか
- [ ] エラーメッセージは有用でありつつ、システムの内部情報をユーザーに漏らしていないか
